# 모바일 실행과 재계획 UI

## 범위

390×844 세로 화면 우선. SwiftUI 전환이 아니라 기존 React와 API 계약을 유지한 표현 계층 개선.
오늘의 기록 상태에 맞춘 우선순위, 공통 여백/글자/컨트롤 크기, 변경 전후 비교, 목표 가독성 개선.
중단 입력 간소화(#361)의 사유 건너뛰기 경로 포함.

## 상태 규칙

- 진행 중: 해당 실행 우선
- 일부 완료/실패/재계획 대기 또는 미확인 작업: 한 항목 확인 우선
- 빈 목록: 계획 추가 안내
- 전체 완료: 기록 확인
- 단순 미접속을 실패로 추정하지 않음

## 저장 경계

방법 선택은 로컬 상태만 변경. 명시적 버튼으로 선택 저장, 후속 화면에서 새 일정 승인.
기존 실행 정보는 재입력하지 않으며 빈 사유는 사실을 추정해 채우지 않음.
수락/승인 idempotency와 실패 재시도 계약 유지.
전체 잔여 학습량 자동 재배분, 일정 취소/되돌리기 API는 이번 범위에 없음.

## 검증

상태별 단위 테스트, 기존 재계획 저장 실패/승인 테스트, 선택만으로 서버 저장하지 않는 회귀 테스트.
브라우저 360/390px 및 데스크톱에서 확인. 발표 캡처는 실제 배포 화면과 테스트 데이터를 구분.
사용자의 실계획을 발표를 위해 임의 완료/삭제하지 않음.
